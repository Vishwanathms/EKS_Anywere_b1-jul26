

# Part 16 – Verify the Actual Data

This is the **key learning point**.

Run:

```bash
kubectl exec -n backup-demo \
  deploy/backup-demo -- \
  cat /usr/share/nginx/html/student.txt
```

Expected:

```text
Student backup test
```

And:

```bash
kubectl exec -n backup-demo \
  deploy/backup-demo -- \
  cat /usr/share/nginx/html/index.html
```

Expected:

```text
EKS Anywhere Velero Backup Lab
```

Students have now demonstrated:

```text
Kubernetes Objects
        +
Persistent Volume
        +
Application Data
        ↓
      BACKUP
        ↓
   DISASTER
        ↓
      RESTORE
        ↓
Kubernetes Objects
        +
Persistent Volume
        +
Application Data
```

# Part 17 – Demonstrate PV/PVC Relationship

Have students inspect:

```bash
kubectl get pvc -n backup-demo
```

Then:

```bash
kubectl get pv
```

Then:

```bash
kubectl describe pvc demo-pvc -n backup-demo
```

Explain:

```text
PVC
 |
 | claims
 v
PV
 |
 | provisioned by
 v
vSphere CSI
 |
 v
vSphere datastore
```

Velero is **not replacing vSphere storage**.

It is providing Kubernetes workload backup/recovery, while the underlying storage remains managed by the storage platform.
