Absolutely. Since your **EKS Anywhere cluster already has Argo CD, MetalLB, Prometheus, Grafana and Loki**, this is a very good end-to-end observability lab.

I recommend making the lab progressively build the following:

```text
                         EKS Anywhere
                              |
             +----------------+----------------+
             |                |                |
          NGINX Pod       Prometheus          Loki
             |                |                |
       access/error logs      |                |
             |                |                |
             v                v                v
       Log Collector      Metrics         Log Storage
             |                |                |
             +----------------+----------------+
                              |
                           Grafana
                       /      |       \
                      /       |        \
                 Metrics     Logs     Alerts
```

For NGINX metrics, **plain NGINX does not expose Prometheus metrics by itself**, so we'll add an **NGINX Prometheus exporter**. For logs, we'll make NGINX write access/error logs to stdout/stderr so your existing Loki collector can collect them.

# Lab: NGINX Observability on EKS Anywhere

## What students will build

By the end of the lab, students will have:

* NGINX application deployed
* NGINX exposed through MetalLB
* NGINX access logs visible in Loki
* NGINX metrics exposed to Prometheus
* Prometheus scraping NGINX metrics
* Grafana dashboard for NGINX
* Prometheus metric alerts
* Grafana/Loki log alerts
* Traffic generated against NGINX to trigger observable changes

# Part 1 — Verify the Existing Monitoring Stack

Before deploying NGINX, students should understand what is already running.

## Step 1 — Check namespaces

```bash
kubectl get ns
```

Look for namespaces such as:

```text
argocd
metallb-system
monitoring
prometheus
grafana
loki
```

Your names may be different.

---

## Step 2 — Find Prometheus

Run:

```bash
kubectl get pods -A | grep -i prometheus
```

Then:

```bash
kubectl get svc -A | grep -i prometheus
```

Example:

```text
monitoring   prometheus-operated   ClusterIP   10.x.x.x
```

Also check:

```bash
kubectl get svc -A | grep -i grafana
```

and:

```bash
kubectl get svc -A | grep -i loki
```

kubectl get svc -A | grep -i grafana

monitoring   grafana   LoadBalancer   10.x.x.x   192.168.230.240

http://<GRAFANA-METALLB-IP>

# Part 3 — Verify Loki

Find Loki:

```bash
kubectl get pods -A | grep -i loki
```

and:

```bash
kubectl get svc -A | grep -i loki
```

Also check the log collector.

Depending on your installation, it could be:

```text
promtail
```

or:

```text
fluent-bit
```

or:

```text
alloy
```

Check:

```bash
kubectl get pods -A | grep -Ei 'promtail|fluent|alloy'
```

This is important.

The architecture should look approximately like:

```text
NGINX
  |
  | stdout/stderr
  v
Log Collector
  |
  v
Loki
  |
  v
Grafana
```
