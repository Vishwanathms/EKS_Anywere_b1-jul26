# Lab 12 – Production Observability on EKS Anywhere

## Exercise 1 – Installing the Monitoring Stack

**Duration:** 60 Minutes

* A dedicated monitoring namespace

* Node Exporter collecting node metrics
* kube-state-metrics collecting Kubernetes object metrics

# Task 1 – Create the Monitoring Namespace

## Why?

Namespaces logically separate Kubernetes resources.

Instead of deploying monitoring components into the **default** namespace, production environments isolate them inside a dedicated namespace.

This makes administration easier.

---

### Create Namespace

Execute

```bash
kubectl create namespace monitoring
```

Expected Output

```
namespace/monitoring created
```

---

### Verify Namespace

Run

```bash
kubectl get namespace monitoring
```

Expected Output

```
NAME          STATUS    AGE
monitoring    Active    5s
```

---

### View All Namespaces

```bash
kubectl get ns
```

You should now see

```
monitoring
```

Checkpoint

# Task 2 – Install kube-prometheus-stack

## What is kube-prometheus-stack?

Instead of installing individual monitoring tools separately, the Kubernetes community provides a production-ready package called **kube-prometheus-stack**.

This package installs:

* Prometheus
* Grafana
* Alertmanager
* Prometheus Operator
* Node Exporter
* kube-state-metrics

Everything is configured automatically.

---

## Step 1 – Add Helm Repository

A Helm repository is similar to an application store.

Add the Prometheus Community repository.

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
```

Expected Output

```
"prometheus-community" has been added
```

---

## Step 2 – Update Helm Repository

Download the latest chart information.

```bash
helm repo update
```

Expected Output

```
Update Complete.
```

---

## Step 3 – Search the Chart

Verify the chart exists.

```bash
helm search repo prometheus-community/kube-prometheus-stack
```

Expected Output

```
NAME

prometheus-community/kube-prometheus-stack
```

---

## Step 4 – Install the Monitoring Stack

Execute

```bash
helm install monitoring prometheus-community/kube-prometheus-stack \
--namespace monitoring
```

The installation takes several minutes.

Wait until Helm finishes.

Expected Output

```
NAME: monitoring

STATUS: deployed
```

---

### What Happens Internally?

Helm creates:

* Deployments
* StatefulSets
* Services
* ConfigMaps
* Secrets
* RBAC Roles
* Service Accounts

Students do not need to create these manually.

# Task 4 – Understand the Installed Components

Before opening Grafana, understand what each component does.

| Component           | Purpose                                                                                        |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| Prometheus          | Collects metrics from Kubernetes and applications                                              |
| Grafana             | Displays dashboards and graphs                                                                 |
| Alertmanager        | Sends notifications when alert rules are triggered                                             |
| Prometheus Operator | Manages Prometheus resources inside Kubernetes                                                 |
| Node Exporter       | Collects Linux host metrics such as CPU, memory, disk, and network                             |
| kube-state-metrics  | Collects information about Kubernetes objects such as Pods, Deployments, Nodes, and Namespaces |

---

# Task 5 – Access Grafana

Now access the Grafana web interface.

For this first lab, the simplest method is **port forwarding**, as it avoids requiring an Ingress or LoadBalancer.

> **Instructor Note:** In a later exercise, you can expose Grafana using MetalLB and NGINX Ingress to demonstrate production-style external access.

### Step 1 – Identify the Grafana Service

```bash
kubectl get svc -n monitoring
```

Locate the service named similar to:

```
monitoring-grafana
```

---

### Step 2 – Start Port Forwarding

Run:

```bash
kubectl port-forward -n monitoring svc/monitoring-grafana 3000:80
```

Keep this terminal window open.

You should see output similar to:

```
Forwarding from 127.0.0.1:3000 -> 3000
```

---

### Step 3 – Open Grafana

Open your web browser and navigate to:

```
http://localhost:3000
```

You should see the Grafana login page.

---

### Step 4 – Retrieve the Grafana Admin Password

The default username is:

```
admin
```

Retrieve the password stored in the Kubernetes secret:

```bash
kubectl get secret monitoring-grafana -n monitoring \
-o jsonpath="{.data.admin-password}" | base64 -d
```

The command prints the generated password.

---

### Step 5 – Log In

Use:

* **Username:** `admin`
* **Password:** *(output from the previous command)*

After logging in, Grafana may prompt you to change the password. For the lab, you may skip or set a simple temporary password if instructed by your trainer.

---
