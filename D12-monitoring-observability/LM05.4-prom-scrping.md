# Part 12 — Install NGINX Prometheus Exporter

Now we move to **metrics**.

NGINX needs an exporter because standard NGINX doesn't expose Prometheus-format metrics.

We will use:

```text
NGINX
  |
  | /stub_status
  v
NGINX Prometheus Exporter
  |
  | /metrics
  v
Prometheus
```

---

# Part 13 — Enable NGINX Stub Status

Modify your ConfigMap.

```bash
kubectl edit configmap nginx-config -n nginx-observability
```

Add:

```nginx
location /nginx_status {
    stub_status;
    allow all;
}
```

The server becomes:

```nginx
server {
    listen 80;

    location / {
        root /usr/share/nginx/html;
        index index.html;
    }

    location /health {
        access_log off;
        return 200 "OK\n";
    }

    location /nginx_status {
        stub_status;
        allow all;
    }
}
```

Restart NGINX:

```bash
kubectl rollout restart deployment nginx \
  -n nginx-observability
```

Check:

```bash
kubectl rollout status deployment nginx \
  -n nginx-observability
```

# Part 14 — Verify Stub Status

Get the pod:

kubectl get pods -n nginx-observability

kubectl exec -n nginx-observability \

Expected:

```text

server accepts handled requests
  10 10 10
Reading: 0 Writing: 1 Waiting: 0
```

Now NGINX has something the exporter can scrape.

# Part 15 — Add NGINX Prometheus Exporter

For a training environment, the cleanest approach is to add the exporter as a **sidecar**.

Edit the Deployment:

```bash
kubectl edit deployment nginx -n nginx-observability
```

Add another container:

```yaml
- name: nginx-exporter
  image: nginx/nginx-prometheus-exporter:1.4.2
  args:
    - "-nginx.scrape-uri=http://127.0.0.1/nginx_status"
  ports:
    - name: metrics
      containerPort: 9113
```

So your pod will contain:

```text
NGINX Pod
 |
 +-- nginx
 |    port 80
 |
 +-- nginx-exporter
      port 9113
```

Check:

```bash
kubectl get pods -n nginx-observability
```

Expected:

```text
READY
2/2
```

Exporter

# Part 17 — Expose Metrics Through Kubernetes Service

Update your Service.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx
  namespace: nginx-observability
spec:
  selector:
    app: nginx
  ports:
    - name: http
      port: 80
      targetPort: 80

    - name: metrics
      port: 9113
      targetPort: 9113

  type: LoadBalancer
```

Apply:

```bash
kubectl apply -f nginx-service.yaml
```

# Part 18 — Tell Prometheus to Scrape NGINX

This depends on how your Prometheus was installed.

For a typical **Prometheus Operator / kube-prometheus-stack** installation, use a `ServiceMonitor`.

First check:

```bash
kubectl get crd | grep servicemonitor
```

If you see:

```text
servicemonitors.monitoring.coreos.com
```

you can use a ServiceMonitor.

Create:

```bash
nano nginx-servicemonitor.yaml
```

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: nginx
  namespace: nginx-observability
spec:
  selector:
    matchLabels:
      app: nginx
  endpoints:
    - port: metrics
      interval: 15s
      path: /metrics
```

However, notice that our Service currently needs the label:

```yaml
app: nginx
```

Therefore update the Service:

```yaml
metadata:
  name: nginx
  namespace: nginx-observability
  labels:
    app: nginx
```

Then:

```bash
kubectl apply -f nginx-service.yaml
kubectl apply -f nginx-servicemonitor.yaml
```

# Part 19 — Important: Prometheus Namespace Selection

A very common problem is:

> ServiceMonitor exists, but Prometheus doesn't scrape it.

Check your Prometheus configuration:

```bash
kubectl get prometheus -A
```

Then:

```bash
kubectl get prometheus -A -o yaml | grep -A10 serviceMonitorNamespaceSelector
```

You need Prometheus to discover:

```text
nginx-observability
```

If your Prometheus is configured to watch all namespaces, you're fine.

If it only watches its own namespace, you'll need to modify the Prometheus configuration accordingly.

# Part 21 — Query NGINX Metrics in Prometheus

Go to:

```text
Graph
```

or:

```text
Query
```

Try:

```promql
nginx_connections_active
```

You should receive a value.

Try:

```promql
nginx_http_requests_total
```

You should see a counter.

Try:

```promql
rate(nginx_http_requests_total[1m])
```

This is more useful.

It tells you:

> How many NGINX requests are happening per second.
