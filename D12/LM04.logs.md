# Task 11

# Install Loki Stack

---

## Why?

Prometheus stores metrics.

It does NOT store logs.

Applications generate thousands of log messages every minute.

Instead of logging into every Kubernetes node,

Loki stores all logs centrally.

---

## Components Installed

| Component | Purpose                 |
| --------- | ----------------------- |
| Loki      | Log Database            |
| Promtail  | Collects Container Logs |
| Grafana   | Searches Logs           |

---

## Step 1

### Add Grafana Repository

```bash
helm repo add grafana https://grafana.github.io/helm-charts
```

Expected

```
"grafana" has been added
```

---

## Step 2

Update Helm Repository

```bash
helm repo update
```

---

## Step 3

Install Loki

```bash
helm install loki grafana/loki \
--namespace monitoring
```

Wait until installation completes.

---

## Step 4

Install Promtail

```bash
helm install promtail grafana/promtail \
--namespace monitoring
```

Promtail runs on every Kubernetes node and continuously watches container log files.

---

## Step 5

Verify Installation

```bash
kubectl get pods -n monitoring
```

Expected

```
loki-0

promtail-xxxxx

grafana

prometheus

alertmanager
```

---

## Step 6

Verify DaemonSet

```bash
kubectl get daemonset -n monitoring
```

Expected

```
promtail

node-exporter
```

---

Checkpoint

Loki is ready.

Promtail is collecting logs.

# Task 14A

# Simulate Application Crash

Instead of deleting Pods manually,

create a faulty Deployment.

---

Create

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: broken-nginx
  namespace: demo

spec:
  replicas: 1

  selector:
    matchLabels:
      app: broken

  template:
    metadata:
      labels:
        app: broken

    spec:
      containers:

      - name: nginx

        image: nginx

        command:

        - "/bin/sh"

        - "-c"

        - "exit 1"
```

---

Apply

```bash
kubectl apply -f broken-nginx.yaml
```

---

Observe

```bash
kubectl get pods -n demo
```

Expected

```
CrashLoopBackOff
```

# Final Challenge

# Root Cause Analysis

Your production application is unavailable.

Use only Grafana and kubectl.

Answer the following:

1. Which Pod failed?

2. Which Namespace?

3. What time did it fail?

4. Was the container restarted?

5. What does the application log show?

6. What Kubernetes Events occurred?

7. What is the root cause?

8. What action would you recommend?
