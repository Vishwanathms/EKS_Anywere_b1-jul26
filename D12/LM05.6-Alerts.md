# Part 27 — Create Prometheus Metric Alert

Now we introduce alerting.

The first alert should be:

> NGINX has too many active connections.

Go to:

```text
Grafana
→ Alerting
→ Alert rules
→ New alert rule
```

Name:

```text
NGINX High Active Connections
```

Query:

```promql
nginx_connections_active
```

Set condition:

```text
IS ABOVE 50
```

For a lab, you can use a small threshold such as:

```text
5
```

because the test environment won't generate production-level traffic.

For example:

```text
WHEN
nginx_connections_active
IS ABOVE
5
FOR
1 minute
```

# Part 28 — Create Request Rate Alert

Create another alert:

```text
NGINX High Request Rate
```

Query:

```promql
rate(nginx_http_requests_total[1m])
```

Condition:

```text
IS ABOVE 10
```

For example:

```text
WHEN
rate(nginx_http_requests_total[1m])
IS ABOVE 10
FOR 2 minutes
```

# Part 29 — Create NGINX Down Alert

This is one of the most useful production alerts.

Use:

```promql
up{job=~".*nginx.*"}
```

Condition:

```text
IS BELOW 1
```

Meaning:

```text
0 = target unavailable
1 = target available
```

Alert:

```text
NGINX Metrics Target Down
```

Condition:

```text
up{job=~".*nginx.*"} == 0
```

For:

```text
1 minute
```

# Part 30 — Create Loki Log Alert

Now we create an alert based on logs.

This demonstrates a very important observability concept:

```text
Metrics Alert
       vs
Logs Alert
```

Go to:

```text
Grafana
→ Alerting
→ Alert rules
→ New alert rule
```

Select:

```text
Loki
```

Query:

```logql
sum(
  count_over_time(
    {namespace="nginx-observability"} |= "404" [5m]
  )
)
```

Set:

```text
IS ABOVE 10
```

Name:

```text
NGINX Too Many 404 Errors
```

Meaning:

> Alert when NGINX generates more than 10 HTTP 404 log entries within five minutes.

# Part 31 — Generate 404 Errors to Trigger Alert

Run:

```bash
for i in {1..100}
do
    curl -s http://$NGINX_IP/invalid-$i > /dev/null
done
```

Then check Grafana:

```text
Alerting
   ↓
Alert rules
```

You should eventually see:

```text
NGINX Too Many 404 Errors
        |
        v
     FIRING
```

# Part 32 — Create a High Traffic Alert

Generate traffic:

```bash
while true
do
    for i in {1..50}
    do
        curl -s http://$NGINX_IP/ > /dev/null
    done
done
```

Your Prometheus query:

```promql
rate(nginx_http_requests_total[1m])
```

should increase.

This should trigger:

```text
NGINX High Request Rate
```

# Part 33 — Test NGINX Down Alert

This is a particularly good student exercise.

Scale NGINX to zero:

```bash
kubectl scale deployment nginx \
  -n nginx-observability \
  --replicas=0
```

Now check:

```bash
kubectl get pods -n nginx-observability
```

Prometheus should eventually report:

```text
UP = 0
```

Grafana should fire:

```text
NGINX Metrics Target Down
```

Then recover:

```bash
kubectl scale deployment nginx \
  -n nginx-observability \
  --replicas=2
```

Watch the alert return to:

```text
Normal
```
