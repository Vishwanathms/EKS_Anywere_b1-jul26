# PART 34 — Configure Delegate Selection

> **This is one of the most important parts of the lab.**

Configure the pipeline's infrastructure/connector execution so that the Kubernetes operations are routed through the appropriate Harness Delegate.

The conceptual execution path is:

```text
Pipeline
   |
   +-- Deploy NGINX
          |
          +-- Kubernetes Connector
                  |
                  +-- Delegate Selector
                          |
                          +-- eks-anywhere-delegate
```

The **Harness SaaS** does not directly need network connectivity to your EKS Anywhere Kubernetes API.

Instead, the Harness Delegate running inside the EKS Anywhere environment performs the Kubernetes operations.

### Multiple Student Environment

For multiple students, use different Delegate Selectors.

For example:

```text
Student01 Pipeline
       |
       +-- Delegate Selector: student01
```

```text
Student02 Pipeline
       |
       +-- Delegate Selector: student02
```

This allows each student's pipeline to use the appropriate Delegate.

Example:

```text
Student01
   |
   +-- Harness Pipeline
          |
          +-- Delegate Selector: student01
                  |
                  +-- Student01 Delegate
                          |
                          +-- Student01 EKS Anywhere Cluster
```

And:

```text
Student02
   |
   +-- Harness Pipeline
          |
          +-- Delegate Selector: student02
                  |
                  +-- Student02 Delegate
                          |
                          +-- Student02 EKS Anywhere Cluster
```

## Important Execution Flow

The complete architecture is:

```text
                  Harness SaaS
                       |
                       |
                       v
                  Pipeline Run
                       |
                       v
             Kubernetes Connector
                       |
                       v
            Harness Delegate Pod
                       |
                       v
               Kubernetes API
                       |
                       v
                EKS Anywhere
                       |
                       v
                    NGINX
```

### What is happening?

1. User starts the pipeline from Harness SaaS.
2. Harness determines which Delegate should execute the operation.
3. The selected Harness Delegate receives the required task.
4. The Delegate communicates with the Kubernetes API.
5. Kubernetes processes the deployment.
6. Kubernetes creates/updates the NGINX resources.
7. Harness receives the execution status from the Delegate.

# PART 37 — Watch the Delegate

While the pipeline is running, open another terminal.

Check the Delegate:

```bash
kubectl get pods -n harness-delegate-ng
```

Then watch the Delegate logs:

```bash
kubectl logs \
  -n harness-delegate-ng \
  deployment/eks-anywhere-delegate \
  -f
```

Students can observe the Delegate participating in the pipeline execution and communicating with Harness.

> **Training Point:**
> This makes the Harness architecture much easier to understand than simply clicking **Run Pipeline**. Students can see that the Harness Delegate acts as the execution component inside the EKS Anywhere environment.

```text
                                     │
                                     │
                                     ▼
                    ┌────────────────────────────────┐
                    │       EKS Anywhere Cluster     │
                    │                                │
                    │  ┌──────────────────────────┐  │
                    │  │ Harness Delegate Pod      │  │
                    │  └────────────┬─────────────┘  │
                    │               │                │
                    │               ▼                │
                    │       Kubernetes API           │
                    │               │                │
                    │               ▼                │
                    │       harness-demo namespace   │
                    │               │                │
                    │               ▼                │
                    │       harness-nginx Deployment │
                    │               │                │
                    │               ▼                │
                    │          NGINX Pods            │
                    └────────────────────────────────┘
```

### Key Learning

```text
Harness SaaS
     ↓
Pipeline
     ↓
Delegate Selector
     ↓
Harness Delegate
     ↓
Kubernetes API
     ↓
EKS Anywhere
     ↓
Application
```

This is the core concept students should remember: **Harness SaaS orchestrates the pipeline, while the Delegate performs the environment-side work.**
