
# PART 8 — Verify Internet Connectivity

The Delegate needs outbound connectivity to Harness.

From a machine that can reach the EKS Anywhere cluster, test:

```bash
curl -I https://app.harness.io
```

Expected:

```text
HTTP/2 200
```

or another successful HTTP response.

Also verify DNS:

```bash
nslookup app.harness.io
```

or:

```bash
dig app.harness.io
```

# PART 9 — Verify EKS Anywhere Can Pull Images

Because the Delegate itself runs as a Kubernetes Pod, the cluster must be able to pull its container image.

Test:

```bash
kubectl create namespace test-image
```

You can later delete this namespace.

Also verify the worker nodes have Internet access.

# PART 13 — Install Harness Delegate

### Recommended classroom approach

Don't type the token directly into shell history if you can avoid it.

For the lab, however, the basic Helm installation concept is:

```bash
helm upgrade -i eks-anywhere-delegate \
  --namespace harness-delegate-ng \
  --create-namespace \
  harness-delegate/harness-delegate-ng \
  --set delegateName=eks-anywhere-delegate \
  --set accountId=<HARNESS_ACCOUNT_ID> \
  --set delegateToken=<DELEGATE_TOKEN> \
  --set managerEndpoint=https://app.harness.io \
  --set replicas=1 \
  --set upgrader.enabled=true
```

Harness's current documentation uses the same Helm chart and parameters, including `delegateName`, `accountId`, `delegateToken`, `managerEndpoint`, `replicas`, and the upgrader setting. ([Harness][1])

### Replace:

```text
<HARNESS_ACCOUNT_ID>
```

with your actual Harness account ID.

And:

```text
<DELEGATE_TOKEN>
```

with the token created earlier.

# PART 17 — Important Teaching Point

At this stage explain:

```text
              HARNESS SAAS

      Pipeline definition
             |
             |
             v
      Harness Manager
             |
             | task
             v
     EKS Anywhere Delegate
             |
             |
             v
      Kubernetes API
             |
             v
       EKS Anywhere
```

The Delegate is **not** Argo CD.

Compare them:

| Feature               | Argo CD             | Harness Delegate               |
| --------------------- | ------------------- | ------------------------------ |
| Model                 | GitOps              | Pipeline execution/integration |
| Control plane         | Argo CD             | Harness SaaS                   |
| Worker                | Argo components     | Delegate                       |
| Primary purpose       | Continuous delivery | CI/CD + integrations           |
| Git polling           | Yes                 | Depends on pipeline            |
| Kubernetes deployment | Yes                 | Yes                            |
| Runs inside cluster   | Yes                 | Yes                            |
| SaaS control plane    | Optional            | Harness SaaS                   |

# PART 18 — Delegate Tags

For a multi-student environment, **tags are very important**.

Instead of allowing every pipeline to select any Delegate, create student-specific delegates/tags.

For example:

```text
Student01

Delegate:
eks-student01

Tag:
student01
```

Student 02:

```text
Delegate:
eks-student02

Tag:
student02
```

This becomes:

```text
Harness
 |
 +-- Student01 Pipeline
       |
       +-- Delegate Selector
               |
               +-- student01
```

This is especially useful for your shared EKS Anywhere training environment.
