PART 7 — Prepare EKS Anywhere

Students should already have their EKS Anywhere cluster.

Verify:

kubectl get nodes

Expected:

NAME                  STATUS   ROLES
eks-node-01           Ready    control-plane
eks-node-02           Ready    <none>

Then:

kubectl get pods -A

Make sure the cluster is healthy.

Also verify:

kubectl cluster-info
PART 8 — Verify Internet Connectivity

The Delegate needs outbound connectivity to Harness.

From a machine that can reach the EKS Anywhere cluster, test:

curl -I https://app.harness.io

Expected:

HTTP/2 200

or another successful HTTP response.

Also verify DNS:

nslookup app.harness.io

or:

dig app.harness.io
PART 9 — Verify EKS Anywhere Can Pull Images

Because the Delegate itself runs as a Kubernetes Pod, the cluster must be able to pull its container image.

Test:

kubectl create namespace test-image

You can later delete this namespace.

Also verify the worker nodes have Internet access.

PART 10 — Install Helm

On the admin Ubuntu VM:

helm version

If Helm isn't installed:

curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash

Verify:

helm version
PART 11 — Add Harness Helm Repository

Harness currently provides the Delegate Helm repository at:

https://app.harness.io/storage/harness-download/delegate-helm-chart/

Add it:

helm repo add harness-delegate \
  https://app.harness.io/storage/harness-download/delegate-helm-chart/

Update:

helm repo update

Search:

helm search repo harness-delegate

You should see:

harness-delegate/harness-delegate-ng

These are the current installation steps documented by Harness.

PART 12 — Create Delegate Namespace

Create:

kubectl create namespace harness-delegate-ng

Verify:

kubectl get ns harness-delegate-ng
PART 13 — Install Harness Delegate
Recommended classroom approach

Don't type the token directly into shell history if you can avoid it.

For the lab, however, the basic Helm installation concept is:

helm upgrade -i eks-anywhere-delegate \
  --namespace harness-delegate-ng \
  --create-namespace \
  harness-delegate/harness-delegate-ng \
  --set delegateName=eks-anywhere-delegate \
  --set accountId=<HARNESS_ACCOUNT_ID> \
  --set delegateToken=<DELEGATE_TOKEN> \
  --set managerEndpoint=https://app.harness.io \
  --set replicas=1 \
  --set upgrader.enabled=true

Harness's current documentation uses the same Helm chart and parameters, including delegateName, accountId, delegateToken, managerEndpoint, replicas, and the upgrader setting.

Replace:
<HARNESS_ACCOUNT_ID>

with your actual Harness account ID.

And:

<DELEGATE_TOKEN>

with the token created earlier.

PART 14 — Verify Delegate Pod

Run:

kubectl get pods -n harness-delegate-ng

Expected:

NAME                                      READY   STATUS
eks-anywhere-delegate-xxxxxxxx-xxxxx      1/1     Running

Check:

kubectl get all -n harness-delegate-ng

You should see resources similar to:

pod
deployment
serviceaccount
PART 15 — Check Delegate Logs

Run:

kubectl logs \
  -n harness-delegate-ng \
  deployment/eks-anywhere-delegate

Look for successful registration/connection messages.

You can also stream the logs:

kubectl logs \
  -n harness-delegate-ng \
  deployment/eks-anywhere-delegate \
  -f

Press:

CTRL+C

to exit.
