Lab: Harness SaaS + EKS Anywhere Delegate
1. Lab objectives

By the end of this lab, students will be able to:

Create a Harness SaaS account.
Create a Harness project.
Create a Harness Delegate Token.
Install the Harness Delegate inside EKS Anywhere.
Verify Delegate registration.
Understand Harness SaaS vs Delegate.
Create a GitHub connector.
Create a Kubernetes connector.
Create a Harness CD pipeline.
Configure the pipeline to use the EKS Anywhere Delegate.
Deploy an NGINX application to EKS Anywhere.
Verify the deployment from both Harness and Kubernetes.

Important concept

The direction is primarily:

EKS Anywhere Delegate
        |
        | HTTPS outbound
        v
Harness SaaS

The Harness SaaS platform does not need direct inbound access to your EKS Anywhere API server.

That is one of the major advantages of the Delegate architecture. Harness describes the Delegate as a lightweight worker installed in your infrastructure that communicates with Harness using outbound HTTP/HTTPS.
