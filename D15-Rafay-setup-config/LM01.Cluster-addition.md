Yes. I checked the **current Rafay documentation** before structuring this. One important terminology point first:

> For your lab, **“Install Rafay Agent” means installing the Rafay Kubernetes Management Operator into the existing EKS Anywhere cluster**. It is not the separate GitOps/Repository Agent or Environment Manager Agent.

Rafay's current documentation describes the Management Operator as the in-cluster agent, normally deployed in the `rafay-system` namespace. It establishes an outbound, mutually authenticated connection to the Rafay SaaS controller over TCP 443; **you do not need to expose an inbound port from your vCenter/EKS Anywhere environment**. ([Rafay Documentation][1])

Your students already have:

```text

        │   │      │                       │   │

        │   │      │                       │   │
```

# IMPORTANT — Do Not Reuse Bootstrap Files

Each imported cluster requires its own bootstrap YAML.

Do **not** do this:

```text
Student 1 bootstrap.yaml
        ↓
Student 2 cluster
        ↓
Student 3 cluster
```

Instead:

```text
Student 1 → bootstrap-01.yaml
Student 2 → bootstrap-02.yaml
Student 3 → bootstrap-03.yaml
```

Rafay explicitly documents that every cluster requires a different bootstrap YAML and that the same bootstrap file cannot be reused across clusters. ([Rafay Documentation][5])

# PART 11 — Troubleshooting

## Problem 1 — `rafay-system` doesn't appear

Check:

```bash
kubectl get ns
```

Then:

```bash
kubectl apply -f eksa-student01-bootstrap.yaml
```

If there is an error, **do not repeatedly apply the YAML**. Read the error first.

---

## Problem 2 — Pods stuck in `Pending`

Run:

```bash
kubectl get pods -n rafay-system
```

Then:

```bash
kubectl describe pod -n rafay-system <pod-name>
```

Look at:

```text
Events:
```

Common causes:

* Insufficient resources
* Scheduling problem
* Node issue
* Network/CNI problem

---

# Problem 3 — Pods stuck in `ContainerCreating`

Run:

```bash
kubectl describe pod -n rafay-system <pod-name>
```

Look for:

```text
Failed to pull image
```

or:

```text
FailedMount
```

or networking errors.

---

# Problem 4 — Connector cannot connect

Check:

```bash
kubectl logs -n rafay-system <rafay-connector-pod>
```

The most likely areas to investigate are:

```text
DNS
 ↓
Internet connectivity
 ↓
Firewall
 ↓
Outbound TCP 443
 ↓
Rafay SaaS connectivity
```

Rafay specifically calls out firewall, DNS, resource availability and network bandwidth as common causes of import problems. ([Rafay Documentation][6])

## Important instructor note

For your **12-student shared training environment**, I would **not** have every student import the same EKS Anywhere cluster into separate Rafay projects unless you deliberately want to demonstrate multi-tenancy. The cleaner lab design is:

```text
              Rafay Organization
                     │
       ┌─────────────┼─────────────┐
       │             │             │
   Project-01    Project-02    Project-03
       │             │             │
   EKS-A-01      EKS-A-02      EKS-A-03
```

If each student has their own EKS Anywhere cluster, this is ideal. If students are sharing one cluster, **do the import once as the platform/admin exercise**, and then use the rest of the class to demonstrate Projects, Teams, RBAC, namespace governance and controlled cluster sharing rather than repeatedly installing the management operator.
