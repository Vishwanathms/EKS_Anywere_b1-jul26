# 5. Lab Rules

Follow these rules throughout the lab.

### Rule 1 — Use your own Rafay project

Do not import your cluster into another student's project.

Example:

```text
Student 01
    |
    +-- Project: eksa-student01
          |
          +-- Cluster: eksa-student01
```

### Rule 2 — Do not reuse another student's bootstrap YAML

Every imported cluster requires its own unique bootstrap YAML.

Rafay's documentation explicitly states that the bootstrap file is cryptographically unique and cannot be reused across clusters.

### Rule 3 — Do not expose the Kubernetes API

Do not create a pfSense port-forward such as:

```text
Internet → Kubernetes API
```

That is not required for this lab.

The required communication is:

```text
EKS Anywhere
      |
      | TCP 443 outbound
      v
pfSense
      |
      v
Internet
      |
      v
Rafay SaaS
```

# 11. Step 6 — Test DNS Connectivity

The EKS Anywhere nodes must be able to resolve Rafay SaaS endpoints.

From a machine that has the same outbound network path as the cluster, test:

```bash
nslookup control.rafay.dev
```

You should receive an IP address.

You can also test:

```bash
nslookup api.rafay.dev
```

If DNS resolution fails, stop and contact the instructor.

Rafay specifically identifies DNS resolution as a prerequisite for imported clusters because the management components must resolve the SaaS controller.

---

# 12. Step 7 — Test HTTPS Connectivity

Test outbound HTTPS connectivity:

```bash
curl -Iv https://control.rafay.dev
```

You are checking that HTTPS traffic can leave the private environment.

The exact HTTP response is less important than confirming that the connection can be established.

The important requirement is:

```text
TCP 443
Outbound
```

Rafay documents TCP 443 outbound as the control-plane communication path.

---

# 13. Step 8 — Verify pfSense Firewall

Your instructor should have already configured the pfSense firewall.

The required traffic is approximately:

```text
Source:
EKS Anywhere network

Destination:
Rafay SaaS endpoints

Protocol:
TCP

Port:
443

Direction:
Outbound

Action:
Allow
```

Rafay's current network-whitelisting documentation lists the controller FQDNs used by managed cluster components, including:

```text
control.rafay.dev
api.rafay.dev
app.rafay.dev
console.rafay.dev
registry.rafay-edge.net
tunnel.rafay-edge.net
```

and additional Rafay relay/proxy FQDNs.

If your training environment uses strict FQDN/IP filtering, the instructor should configure the complete current Rafay allowlist rather than relying only on one hostname.

# 32. Step 27 — Final Architecture Verification

At this point, your environment should look like:

```text
                         Rafay SaaS
                             |
                             |
                        TCP 443
                             |
                             |
                         pfSense
                             |
                       Private Network
                             |
                 +-----------+-----------+
                 |                       |
          EKS-A Control Plane       EKS-A Worker
                 |
                 |
           rafay-system
                 |
       +---------+---------+
       |         |         |
   Connector  Controller  Relay
       |
       |
   Outbound mTLS
       |
       +------------------------>
                 Rafay SaaS
```

No inbound Kubernetes API access from the Internet is required.

Rafay's network documentation specifically describes this architecture for private/on-premises clusters: the Kubernetes management operator establishes the outbound control channel, and no inbound external firewall port is required for control-plane traffic.

# 34. Troubleshooting

## Problem 1 — `kubectl apply` fails

Run:

```bash
kubectl config current-context
```

Then:

```bash
kubectl get nodes
```

If you cannot access the cluster, fix your Kubernetes connectivity first.

---

## Problem 2 — `rafay-system` does not appear

Run:

```bash
kubectl apply -f eksa-student01-bootstrap.yaml
```

Check the command output carefully.

If there is an RBAC or Kubernetes API error, contact the instructor.

---

## Problem 3 — Pods remain Pending

Run:

```bash
kubectl get pods -n rafay-system
```

Then:

```bash
kubectl describe pod -n rafay-system <pod-name>
```

Check:

```text
Events
```

Common causes include:

* insufficient cluster resources
* image pull problems
* network connectivity
* DNS problems
* firewall restrictions

Rafay identifies firewall, DNS, cluster resources, and network bandwidth as common causes of failed imported-cluster registration.

---

# 35. Problem 4 — Connector Cannot Connect to Rafay

Run:

```bash
kubectl get pods -n rafay-system
```

Find the connector pod.

Then:

```bash
kubectl logs -n rafay-system <connector-pod>
```

Look for connection errors involving Rafay endpoints.

Test DNS:

```bash
nslookup control.rafay.dev
```

Test HTTPS:

```bash
curl -Iv https://control.rafay.dev
```

If DNS works but the HTTPS connection fails, check pfSense.

The required control-plane path is:

```text
EKS-A
  |
  | TCP 443 outbound
  v
pfSense
  |
  v
Internet
  |
  v
Rafay
```

Rafay's current documentation states that the management operator uses outbound TCP 443 and a long-running mTLS control channel.

---

# 36. Problem 5 — Rafay Shows the Cluster but It Does Not Synchronize

Check:

```bash
kubectl get pods -n rafay-system
```

All relevant pods should be Running.

Then:

```bash
kubectl logs -n rafay-system <rafay-connector-pod>
```

Also verify that the cluster can continuously reach the Rafay SaaS endpoints.

Do not immediately delete and reinstall the Rafay components.

First collect:

```bash
kubectl get pods -n rafay-system
kubectl get events -n rafay-system --sort-by=.lastTimestamp
```

and provide the output to the instructor.

---

# 37. Problem 6 — Student Cannot See the Cluster in Rafay

Verify:

```text
User
  ↓
Correct Project
  ↓
Infrastructure Admin
  ↓
Infrastructure → Clusters
```

Make sure the cluster was created in **your project**.

For example:

```text
student01
    |
    +-- eksa-student01
```

not:

```text
student01
    |
    +-- eksa-student02
```

Rafay uses projects as logical isolation boundaries, and imported clusters are associated with the project in which they are created.
