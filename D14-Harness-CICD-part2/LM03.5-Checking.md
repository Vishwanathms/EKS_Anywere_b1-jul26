# 51. What Each Component Does

| Component         | Responsibility                              |
| ----------------- | ------------------------------------------- |
| GitHub            | Source code + deployment manifest           |
| Harness SaaS      | Pipeline orchestration                      |
| Linux CI VM       | Executes CI workload                        |
| Docker Delegate   | Connects local CI infrastructure to Harness |
| Docker Runner     | Executes CI build actions                   |
| Docker            | Builds container image                      |
| Docker Hub        | Stores container image                      |
| Harness CI        | Build/Test/Package/Publish                  |
| Harness CD        | Deploy/Verify/Rollback                      |
| Existing Delegate | Executes CD operations against EKS Anywhere |
| EKS Anywhere      | Runs application                            |
| Kubernetes        | Performs rollout                            |

Harness currently describes CI as an end-to-end workflow that can pull source, build artifacts, and upload them to a registry such as Docker Hub. ([Harness][5])
