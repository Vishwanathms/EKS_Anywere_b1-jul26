# PART 10 — UPDATE THE KUBERNETES MANIFEST

## 28. Understand the Problem

The new image exists:

```text
docker.io/student123/python-redis-app:5
```

But the manifest may still contain:

```yaml
image: docker.io/student123/python-redis-app:4
```

We need to change it automatically.

---

# 29. Add Manifest Update Step

Add:

```text
Run
```

Name:

```text
Update Kubernetes Manifest
```

Command:

```bash
IMAGE_TAG="<+pipeline.sequenceId>"

sed -i \
"s#image: .*python-redis-app:.*#image: docker.io/YOUR_DOCKERHUB_USER/python-redis-app:${IMAGE_TAG}#" \
manifests/python-deployment.yaml

echo "New image:"
grep "image:" manifests/python-deployment.yaml
```

Replace:

```text
YOUR_DOCKERHUB_USER
```

with the actual Docker Hub username.

---

# 30. Verify the Manifest Update

Example before:

```yaml
image: docker.io/student123/python-redis-app:4
```

After:

```yaml
image: docker.io/student123/python-redis-app:5
```

The Harness log should show:

```text
New image:
docker.io/student123/python-redis-app:5
```

# PART 11 — PUSH THE MANIFEST BACK TO GITHUB

## 31. Configure Git Credentials

The Linux CI workspace needs permission to push to GitHub.

Use the GitHub connector/credentials that already have repository write permissions.

Do not put a GitHub password directly in the shell command.

---

# 32. Add Commit Step

Add:

```text
Run
```

Name:

```text
Commit Manifest
```

Command:

```bash
git config user.name "Harness CI"
git config user.email "harness-ci@local"

git add manifests/python-deployment.yaml

git commit -m "Update Python image to <+pipeline.sequenceId>"

git push origin HEAD:main
```
